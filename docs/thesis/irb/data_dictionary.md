# Data Dictionary — AEGIS Bot Detection Study

_Generated by `generate_data_dictionary.py` from the code that collects the data (`contracts/features.json`, `study/aegis_study/`), so this list cannot drift from the software._

Everything below is recorded only **after** the participant has given consent on the study website. Sections 1, 2, 4 and 5 apply to every participant; section 3 only to participants who also tick the **optional** raw-timing box. Bot sessions run by the researcher are recorded the same way.

## 1. Behavioural summary features (every participant)

Aggregate numbers computed in the participant's browser (mouse, keyboard, scroll, touch, fingerprint) or on the study server (session, network), reported every 15 seconds while a page is open and when it is left.

## 2. Session, survey and task progress (every participant)

| Field | Content | Identifying? |
|-------|---------|--------------|

| `session_no`, `started`, `finished`, `status` | Which session of this code, start/end time, completed or not | No |
| `lang`, `consent_version`, `consent_at`, `raw_consent` | Language, version and time of the consent, whether the optional raw-timing box was ticked | No |
| `ua_family`, `ua_major`, `os_family`, `mobile` | Browser family and major version (e.g. Chrome 141), operating system family (e.g. Android), phone or not. The full browser identification string is not stored | No |

## 3. Raw timing events (only with the optional consent)

The times and screen positions of individual input events in the study website, so that the summary features can be recomputed and checked later. Each event is a type, a time in milliseconds since the page was opened, and the fields below. Positions are in pixels of the browser window.

| Type | Fields | Meaning |
|------|--------|---------|
| `m` | x, y, pointer type, [pressure, contact width, height] | pointer moved (every coalesced sample) |
| `d` | x, y, pointer type, button, element role | pointer pressed |
| `u` | x, y, pointer type, button | pointer released |
| `c` | x, y, element role, element box (left, top, width, height) | click and the size and place of what was clicked |
| `w` | delta x, delta y, delta mode | mouse wheel |
| `s` | scroll x, scroll y | page scroll position |
| `k` | key category, press number, form field name, repeat flag | key pressed (category only, never which key) |
| `K` | key category, press number | key released |
| `i` | input type, form field name | kind of input event, e.g. typed, pasted, autofilled (never the text) |
| `p` | form field name | paste (never the pasted content) |
| `f` | form field name | form field focused |
| `b` | form field name | form field left |
| `v` | visible 0/1 | browser tab shown or hidden |
| `r` | viewport width, height, pixel ratio, screen width, height | window size (at start and on resize) |
| `n` | page width, height | page loaded |
| `e` | – | page left |

Instead of the key, only one of these categories is recorded: `c` character key (which one is not recorded); `s` space; `b` Backspace; `d` Delete; `e` Enter; `t` Tab; `h` Shift; `m` Ctrl/Alt/Meta/CapsLock; `a` arrow or navigation key; `i` input-method composition (e.g. Bangla keyboards); `o` other. The "press number" only pairs a key's press with its release. Form fields are identified by their name in the study shop (e.g. `username`, `note`), never by their content. Element roles are labels of the study shop's own buttons and links (e.g. `button:add-to-cart`).

## 4. Request metadata (every request to the study website)

| Field | Content | Identifying? |
|-------|---------|--------------|
| `route`, `method`, `status`, `duration_ms`, `at` | Page pattern without ids or search text (e.g. `/shop/product/{id}`), method, response status, time | No |
| `header_names`, `header_flags` | Names and order of the browser's request headers, and whether certain headers are present (no header values) | No |
| `ua_family`, `ua_major`, `os_family` | As in section 2 | No |
| `aegis_action`, `aegis_score`, `aegis_reason` | Detection output for the request | No |

Requests made before consent, or by visitors without a study code, are stored without any link to a participant ("unlabelled") and are analysed separately.

## 5. Processed but NOT stored

| Data | Why it is processed | Retention |
|------|--------------------|-----------|
| IP address | Network features (datacenter/Tor flags), limiting wrong study-code attempts | Memory only. No access logs are written |
| Full browser identification string (user agent) | Header checks; a hash binds the token to the browser | Memory only |
| Header values, search text, form contents (username, password, address, notes, reviews) | Showing the shop and checking whether a task was completed | Memory only, during the request |
| Device fingerprint hash | Session consistency check | Memory only |
| Cookies `aegis_sid` and `study_sid` | Group the requests of one visit | Expire after the visit (30 min inactivity / 6 h) |

## 6. Never collected

- Which keys were pressed or any typed text (the login and delivery details are invented values given by the site)
- Screenshots, screen recordings, webcam, microphone, location, device motion
- Clipboard content (only that a paste happened)
- Browsing history or activity on other sites or other browser tabs
- Names, e-mail addresses or phone numbers of participants (only on the paper consent form / the researcher's separate key list)
